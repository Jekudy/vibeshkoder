# GitHub-Native Sprint Planning

This instruction replaces BMAD's file-system sprint tracker for this project.

1. Read the planning artifacts and project context.
2. Treat epics and story files as supporting input, never as backlog or status authority.
3. Search GitHub Issues for every proposed epic and story. Update matching issues; create the
   missing Discovery/RFC or Implementation Work issues with problem, scope, acceptance
   criteria, validation plan, dependencies, and artifact links.
4. Use existing repository labels only. Do not invent local status values or a parallel state
   machine.
5. Report the resulting issue URLs and dependency order.

Do not create, read, or update `sprint-status.yaml`. After syncing GitHub Issues, execute the
mandatory GitHub Issue handoff and exit without running the standard file-system steps.
