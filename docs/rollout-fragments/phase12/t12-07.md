- **Migration 077**: new `butler_undo_invocations` audit table + widens
  `ck_butler_actions_status` CHECK to include `'undone'`.
- **`ButlerUndoInvocation` ORM + `ButlerUndoInvocationRepo`**: flush-only, caller
  owns transaction. UNIQUE `(butler_action_id, butler_tool_invocation_id)`.
- **Forget cascade tail**: `butler_undo_invocations` layer inserted between
  `butler_tool_invocations` and `butler_actions` in `CASCADE_LAYER_ORDER`.
  `_cascade_butler_undo_invocations` redacts `error_message` on undo rows tied
  to the forget event.
- **`ButlerCardSuggestionRepo.dismiss_by_undo`**: rejects linked
  `extraction_candidate` (pending → rejected) for the `cancel_pending`
  rollback path. `ButlerCardSuggestion` has no status column — rejection
  propagates to the linked EC.
- **`ButlerService.execute_undo`**: LIFO rollback over `butler_tool_invocations`
  ordered by `invocation_seq DESC`. For each invocation: creates undo row as
  `pending`, dispatches `rollback_kind` handler
  (`not_reversible` / `delete_message` / `edit_message` /
  `followup_correction` / `cancel_pending`), updates undo row to
  `succeeded` / `failed` / `skipped_not_reversible`.
  - Auth: requester, admin, OR affected_user (spec PLAN.md §728/DESIGN §470/charter §91);
    raises `ButlerActionError(forbidden)` otherwise.
  - Status gate: only `succeeded` or `undone` actions proceed (idempotency on
    `undone`).
  - TTL: configurable via `BUTLER_UNDO_TTL_MINUTES` env var (default 60 min),
    checked against `executed_at`. Raises `ButlerActionError(ttl_expired)`.
  - Idempotency: if all undo rows already terminal, returns existing summary
    immediately.
  - `FOR UPDATE NOWAIT` on `butler_actions` row matches T12-04 cascade guard
    pattern.
- **`/butler_undo` handler** (replaces T12-05 stub): dual flag gate
  (`memory.butler.enabled` master + `memory.butler.undo.enabled` sub-flag,
  both default OFF). Sub-flag OFF shows stub message to members, silent to
  non-members. Full error routing: `CascadeInFlightError`, `ButlerActionRejectedError`,
  `ButlerActionError` by kind (`ttl_expired`, `wrong_status`, `not_found`,
  `forbidden`). Success renders step-by-step HTML summary.

## Risk

**LOW.** All `memory.butler.*` flags remain default OFF. `memory.butler.undo.enabled`
is a new sub-flag defaulting OFF — the undo surface is unreachable even if the
master flag is ON. Migration 077 creates a new table and widens an existing CHECK
constraint — safe on empty table.

## Operator Steps

NONE at deploy time. No flag flip required. Undo surface unreachable while
`memory.butler.undo.enabled = False`. Migrations 077 + 078 add new table and
column — safe on empty table.

Forget cascade redaction of `error_message` on undo audit rows runs automatically
at next forget event — no operator action needed.

Enable undo after verifying tool implementations (T12-06) are working:

```sql
-- Enable master butler flag first (if not already):
INSERT INTO feature_flags (flag_key, enabled, scope_type, scope_id)
VALUES ('memory.butler.enabled', true, NULL, NULL)
ON CONFLICT (flag_key, scope_type, scope_id) DO UPDATE SET enabled = true;

-- Then enable undo:
INSERT INTO feature_flags (flag_key, enabled, scope_type, scope_id)
VALUES ('memory.butler.undo.enabled', true, NULL, NULL)
ON CONFLICT (flag_key, scope_type, scope_id) DO UPDATE SET enabled = true;
```

TTL is controlled by env var `BUTLER_UNDO_TTL_MINUTES` (default 60). Set in Coolify
environment if a different window is required.

## Rollback

Disable `memory.butler.undo.enabled` flag — undo handler silently no-ops for all
members; existing undo rows stay in DB but no new undos are invocable.

Full revert: `alembic downgrade 078 → 077 → 076` + revert PR. Safe — both
`butler_undo_invocations` and `inverse_op_payload` column have no production rows
(undo surface gated behind `memory.butler.undo.enabled = False`).

## 5 Rollback Kinds

| `rollback_kind` | Mechanism | Undo row status on success |
|-----------------|-----------|---------------------------|
| `not_reversible` | Skip (no Telegram call) | `skipped_not_reversible` |
| `delete_message` | `bot.delete_message(chat_id, message_id)` | `succeeded` |
| `edit_message` | `bot.edit_message_text(text, chat_id, message_id)` | `succeeded` |
| `followup_correction` | `bot.send_message(chat_id, text)` | `succeeded` |
| `cancel_pending` | `ButlerCardSuggestionRepo.dismiss_by_undo(session, action_id)` → EC pending → rejected | `succeeded` |

## Migrations Applied

**077_butler_undo_invocations.py** — creates `butler_undo_invocations` table:
- `id` BIGSERIAL PK
- `butler_action_id` BIGINT FK → `butler_actions.id` ON DELETE RESTRICT
- `butler_tool_invocation_id` BIGINT FK → `butler_tool_invocations.id` ON DELETE RESTRICT
- `requester_user_id` BIGINT NOT NULL
- `rollback_kind` VARCHAR(64) NOT NULL + CHECK (5 values)
- `status` VARCHAR(64) NOT NULL DEFAULT `'pending'` + CHECK (4 values: `pending`, `succeeded`, `failed`, `skipped_not_reversible`)
- `error_kind` TEXT NULLABLE, `error_message` TEXT NULLABLE
- `created_at` TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now()
- UNIQUE `uq_butler_undo_invocations_action_invocation` on `(butler_action_id, butler_tool_invocation_id)`
- INDEX `ix_butler_undo_invocations_butler_action_id`

Also widens `ck_butler_actions_status` CHECK to include `'undone'`. Alembic head: 076 → 077.

**078_butler_tool_invocations_inverse_op_payload.py** — adds `butler_tool_invocations.inverse_op_payload` JSONB:
- `inverse_op_payload` JSONB NULLABLE — populated by `execute_action` after `tool.build_inverse(result)`
- Used by `execute_undo` LIFO dispatch to recover per-invocation reversal data without re-querying tool logic
- Alembic head: 077 → 078.
