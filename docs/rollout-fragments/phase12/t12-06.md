# T12-06 Rollout Fragment

## Summary

Lands 5 concrete Butler tool implementations (spec PHASE12_PLAN_REFRESH.md §10 T12-06)
under `bot/services/butler_tools/`:

- **`recall_evidence`** — delegates all memory reads to the sealed `ButlerEvidenceContext`
  (no direct DB access); returns evidence_ids + context_hash; rollback_kind=`not_reversible`
  (no Telegram side effect to undo).
- **`schedule_meeting`** — posts a Telegram-native text-only proposal to the originating
  chat; no calendar API (Hard Constraint #6); rollback_kind=`delete_message`.
- **`send_intro`** — sends the confirmed intro text from args (never re-fetched from DB);
  rollback_kind=`delete_message`; intro_text never logged or included in payload (privacy).
- **`update_intro`** — verifies Butler ownership via action_repo; on success edits the message
  (`rollback_kind='edit_message'`); if edit unavailable (not Butler's message or 48h timeout),
  posts a follow-up reply (`rollback_kind='followup_correction'`) — no exception raised.
- **`suggest_card_creation`** — writes `extraction_candidates` (status=`pending`) +
  `butler_card_suggestions` mapping row atomically via `session.add()+flush()`; NEVER creates
  a card with status=`approved`; rollback_kind=`cancel_pending`.

Also adds `TOOL_DISPATCH: dict[str, ButlerTool]` to `bot/services/butler_tools/__init__.py`
mapping all 5 tool names to their singleton instances. `TOOL_DISPATCH` keys are asserted to
exactly match `ALLOWED_BUTLER_TOOLS` at module load time.

Round-2 fixes applied after review:
- `ButlerTool` Protocol extended with `invocation_repo` kwarg — full execute signature:
  `execute(ctx, args, *, session, bot, action_repo, invocation_repo, action_id)`.
- 15 `getattr(args, X, default)` calls removed across all 5 tools; each raises
  `ButlerPlanError(invariant_broken)` on wrong arg type.
- `action_id` required (no default) in `suggest_card_creation.execute()`; defense guard
  raises `invariant_broken` on `action_id == 0`.
- `parse_mode=None` pinned on `send_intro`, `schedule_meeting`, `update_intro` send/edit/followup paths.
- `except` in `update_intro` narrowed to `(SQLAlchemyError, OperationalError)`.
- `ButlerService.execute_action` extracts `message_id` from `result.payload` for
  `send_intro` / `schedule_meeting` and persists via `ButlerToolInvocationRepo.update_invocation(posted_message_id=...)`.
- `update_intro` ownership check via `invocation_repo.find_by_posted_message_id(...)` is now
  fully wired end-to-end (was dead code before round-2 `posted_message_id` column existed).

## Hard Constraints Honored

- **#1 NO LLM** — zero anthropic/openai/llm_gateway imports in any tool file.
- **#2 NO raw DB outside repos** — `recall_evidence` issues zero session.execute() calls;
  `suggest_card_creation` uses only `session.add()+flush()` on ORM objects.
- **#6 no calendar/email/browser/shell** — `schedule_meeting` issues only `bot.send_message`.
- **Privacy** — `intro_text` (send_intro / update_intro) and `query` text (recall_evidence)
  NEVER appear in logs or result payload. `tests/services/butler_tools/test_send_intro.py`
  and `test_recall_evidence.py` assert this explicitly.
- **inverse_op_payload determinism** — same ToolResult produces identical bytes for all 5 tools.
- **Tombstone read-side convention** — not applicable (T12-06 tools do not query forget_events).

## Cross-Stream Contracts

- **T12-04 `ButlerService.execute_action`** calls tool via `tool_registry[tool_name]` kwarg;
  `TOOL_DISPATCH` is the canonical registry instance to pass. Round-2: `execute_action` also
  threads `invocation_repo=self._invocation_repo` and `action_id=action_row.id` to every tool.
- **T12-05** handlers pass the real `Bot` instance to `execute_action` so tools can call
  `bot.send_message` / `bot.edit_message_text` (pattern: Phase 7 FHR `event._runtime_bot = bot`).
- **T12-07 undo** reads `inverse_op_payload` from `butler_actions.inverse_op_payload`
  (written by `execute_action` after `build_inverse()`). Shape per tool:
  - `recall_evidence`: `{rollback_kind: not_reversible}`
  - `schedule_meeting`: `{rollback_kind: delete_message, chat_id, message_id}`
  - `send_intro`: `{rollback_kind: delete_message, target_user_id, message_id}`
  - `update_intro` (edit): `{rollback_kind: edit_message, message_id, chat_id}`
  - `update_intro` (followup): `{rollback_kind: followup_correction, followup_message_id, chat_id}`
  - `suggest_card_creation`: `{rollback_kind: cancel_pending, butler_card_suggestion_id, candidate_id}`
