### Runtime guard: empty-evidence abstention in `plan_action`

A new "Step 2b" check in `ButlerService.plan_action` rejects planning when
`evidence_context.bundle.abstained is True` **before** the LLM gateway call.

**Why:** An empty-citation `ButlerEvidenceContext` (abstained bundle) reaching the
gateway allows the LLM to hallucinate a plan with no grounded evidence. This is a
privacy gap — the resulting plan payload can reference members or message content
that is unverifiable or tombstoned. The guard closes this by treating abstained
evidence as a hard stop, mirroring the `budget_exceeded` sibling path from T12-08.

**Rejection path:**
1. `evidence_context.bundle.abstained` is `True` at Step 2b
2. A `butler_actions` row is written with `status='rejected'`, `rejection_reason='empty_evidence'`, `llm_usage_ledger_id=NULL` (no gateway call made)
3. `ButlerActionError(error_kind='empty_evidence')` is raised
4. Handler maps `'empty_evidence'` error_kind → `_MSG_EMPTY_EVIDENCE` in `bot/handlers/butler.py`

This is additive to the existing `budget_exceeded` path — no existing code paths are
modified beyond the `plan_action` guard insertion and the handler routing table.

**Regression coverage:** A dedicated regression test was added to `tests/services/test_butler_plan_action.py` asserting that the `empty_evidence` error path produces no ledger row and that the handler LOW finding (routing) is green.
