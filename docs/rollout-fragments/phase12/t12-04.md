# T12-04 Rollout Fragment

## Summary

Lands `ButlerService` — the orchestrator-only state machine for butler actions
per `PHASE12_PLAN.md` §5.D / §5.E: five transition methods (`plan_action`,
`confirm_action`, `execute_action`, `cancel_action`, `expire_action`), full
exception hierarchy (`ButlerActionError` + 5 subclasses each carrying
`error_kind` + `action_id`), MSK-aligned atomic rate buckets with
decrement-on-failure rollback, cross-user consent re-verified at
`execute_action` BEFORE tool invocation (Hard Constraint #5), evidence
revalidation on all-confirmed via `ButlerEvidenceContext` (Hard Constraint
#3), and cascade-vs-callback race guard via `SELECT FOR UPDATE NOWAIT` on
butler_actions parent BEFORE child confirmation updates inside
`_cascade_butler_action_confirmations`. Foundation for T12-05 (Telegram
handlers) and T12-06 (tool wrappers).

## Risk

**MEDIUM.** Migration 074 adds 4 NOT NULL columns to existing `butler_*`
tables (which are empty — Phase 12 is new, no rows yet). No flag flipped.
No surface added (T12-05 lands handlers). All `memory.butler.*` flags
remain default OFF. Code is unreachable from any registered handler until
T12-05.

  `plan_payload JSONB NOT NULL`.
- `butler_action_confirmations`: adds `confirmation_token TEXT NOT NULL`

Status enum unchanged (uses migration 070's CHECK). Each NOT NULL column
keeps a `server_default` so upgrade-then-downgrade is safe on empty tables
— no orphan row possibility because Phase 12 has zero production rows
prior to T12-05 surface enablement.

## Hard Constraints Honored

- **#1 NO LLM outside gateway** — `plan_action` delegates to
  `llm_gateway.plan_butler_action`; no direct anthropic/openai imports in
  `butler.py`.
- **#2 NO raw DB outside repos** — all DB access via `ButlerActionRepo`,
  `ButlerActionConfirmationRepo`, `ButlerToolInvocationRepo`,
  `ButlerRateBucketRepo`; no raw SQL in `butler.py`.
- **#3 NO raw pre-redaction content** — evidence revalidation delegated to
  `ButlerEvidenceContext`; `butler.py` never reads raw forgotten content.
- **#5 cross-user consent unbypassable** — `plan_action` creates
  individual confirmation rows for all `affected_user_ids`;
  `confirm_action` checks all rows before advancing to
  `pending_execution`; `execute_action` re-verifies consent BEFORE tool
  invocation (`affected_user_consent_revoked` rejection path).
- **#6 no money/calendar/email/browser/shell** — `butler.py` imports zero
  modules from those families; tool registry is the only execution
  surface and `ALLOWED_BUTLER_TOOLS` is closed-list (T12-03).
- **#9 NULL ledger only for rejected/expired/cancelled** — `plan_action`
  writes `llm_usage_ledger_id` from gateway's ledger FK on every
  non-rejected path; CHECK constraint
  `ck_butler_actions_ledger_required_post_plan` enforces invariant
  database-side.
- **#11 fe.tombstone_key 3-key prefix** — evidence revalidation uses the
  `fe.tombstone_key` prefix predicate inside `ButlerEvidenceContext`
  (read-side convention; write-side stays in `forget_cascade.py`).

## Cross-Stream Contracts

- **T12-05** (Telegram handlers) consumes `ButlerService` methods
  directly; rate buckets pre-populated by `plan_action` so handlers don't
  re-implement them. Handlers receive `confirmation_token` from
  `plan_action` return tuple and pass it back into `confirm_action`.
- **T12-06** `ButlerTool` implementations satisfy the Protocol at
  `bot/services/butler_tools/__init__.py`; the registry resolver lookup
  inside `execute_action` will return their instances.
- **T12-07** undo flow reads `butler_actions.parent_action_id` plus
  `inverse_op_payload` from `butler_tool_invocations` (the
  `update_invocation()` repo method writes the inverse payload).
- **T12-08** TTL reaper job calls `ButlerService.expire_action`
  periodically. Per-`call_type` monthly cost filter (C9 extension) still
  TODO — current guard is the daily `BUTLER_DAILY_USD_CEILING=$1` set in
  T12-03.

## 8 §5.B Rejection Paths (at `plan_action`)

`tool_not_allowed`, `invalid_args`, `evidence_context_mismatch`,
`orphan_evidence_ids`, `budget_exceeded`, `membership_revoked`,
`cross_user_consent_required_but_self_chat`, `rate_limit_exceeded`.

## 5 Transition-Time Rejections (at `confirm_action` / `execute_action`)

`already_confirmed`, `bad_token`, `expired`, `evidence_stale`,
`cascade_in_flight`, `source_forgotten`, `affected_user_consent_revoked`.

## Rate Buckets

- Plan time: `user_plans_day`, `chat_actions_day`, `tool_hour:<tool>`
  (atomic ON CONFLICT increment).
- Execute time: `user_execs_day` (atomic ON CONFLICT increment).
- All failure paths after a successful increment trigger
  `ButlerRateBucketRepo.decrement` rollback.
