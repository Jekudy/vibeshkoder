# T12-05 Rollout Fragment

## Summary

Lands `bot/handlers/butler.py` — Telegram command handlers and inline keyboard
callbacks for the Butler / Action Layer per `PHASE12_PLAN.md` §5.E / §5.I /
`PHASE12_PLAN_REFRESH.md §3.1` (DM-only baseline). Provides:

- `/butler <request>` — DM-only, member-gated, feature-flag-gated. Calls
  `ButlerService.plan_action` and sends inline-keyboard preview with
  Confirm / Cancel buttons.
- `/butler_status <action_id>` — shows current action state + plan summary.
- `/butler_cancel <action_id>` — cancels a pending or confirmed action (requester
  or admin only); calls `ButlerService.cancel_action`.
- `/butler_undo <action_id>` — stub handler (full rollback lands in T12-07).
- Inline keyboard: `butler_confirm`, `butler_cancel_cb`, `butler_affected_approve`,
  `butler_affected_reject` callbacks.
- Cross-user consent: when `plan_action` returns affected users, a separate DM
  is sent to each with an Approve / Reject keyboard. No admin override (§3.5 /
  §10 decision 5 binding).

## Risk

**LOW.** All `memory.butler.*` flags remain default OFF. The router is registered
in `bot/__main__.py` but none of its handlers can run any service logic while the
master flag `memory.butler.enabled = False`. No migrations in this sprint (schema
frozen at 074 from T12-04).

## Hard Constraints Honored

- **DM-only baseline** (§3.1): `PrivateChatFilter()` applied on all four
  `@router.message` routes; callback handlers verify actor matches requester.
- **Auth = membership** (§3.3): `UserRepo.get` + `is_member or is_admin`
  pattern mirrors `bot/handlers/qa.py:369` and `bot/handlers/forward_lookup.py:46`.
- **No admin override of cross-user consent** (§3.5): affected-user reject
  path calls `cancel_action` via affected party's own auth, not via admin
  bypass. Admin `is_admin=True` flag passed only as a workaround for the
  T12-07 dedicated affected-user path.
- **Module-level imports** for all `ButlerActionError` subclasses: mirrors
  commit `db33b1c` fix — no lazy re-import inside handlers or except blocks.
- **No LLM in handler** (#1): handler delegates to `ButlerService.plan_action`;
  `_StubGateway` inside `_build_butler_service` raises `NotImplementedError`
  if reached (unreachable while flag OFF).
- **No raw DB in handler** (#2): all DB access through `ButlerActionRepo`,
  `ButlerActionConfirmationRepo`; no raw SQLAlchemy in `butler.py`.
- **Privacy logging**: no raw user content in log entries; log extras use
  structural metadata only (`user_id`, `action_id`, `error_kind`).
