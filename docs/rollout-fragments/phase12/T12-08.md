# T12-08 Rollout Fragment — Butler TTL expiry worker + abuse controls

## What shipped

- **`bot/services/butler_budget.py`** — per-user-day budget guard:
  - `ButlerBudgetChecker.is_user_daily_exceeded(session, user_id, spend_fn)` — returns True when user >= ceiling
  - `compute_user_daily_budget_spent(session, user_id)` — SUMs `llm_usage_ledger.cost_usd` via JOIN on `butler_actions.llm_usage_ledger_id` for current MSK calendar day, filtered to `call_type IN ('butler_decision','butler_summary')`
  - Ceiling: `BUTLER_PER_USER_DAILY_USD_CEILING` env var (default `0.20` USD)

- **`bot/services/scheduler.py`** — TTL expiry worker:
  - `butler_expire_tick(*, bot, session)` — inner tick; queries stale `pending_confirmation` rows via `_query_pending_past_ttl`, calls `ButlerService.expire_action` per row, returns expired count
  - `butler_expire_tick_job(bot)` — APScheduler wrapper; gated by `memory.butler.enabled` flag; bot threaded via `args=[bot]` (T7 FHR F2 pattern)
  - Job ID: `butler_expire_tick`; interval: `BUTLER_EXPIRE_TICK_SECONDS` (default 60s)

- **`bot/db/repos/butler_action.py`** — `get_pending_past_ttl(session, *, now)` static method

- **`bot/db/repos/llm_usage_ledger.py`** — `monthly_cost_usd` gains `call_type: str | None = None` kwarg (C9 / T12-08 spec requirement)

## No migration

Budget tracking uses existing `llm_usage_ledger ↔ butler_actions.llm_usage_ledger_id` JOIN. No new DB column needed.

## Operator steps (post-deploy)

None. The TTL worker only runs when `memory.butler.enabled = true` (default OFF). No flag to flip.

## Env vars added

| Var | Default | Purpose |
|---|---|---|
| `BUTLER_PER_USER_DAILY_USD_CEILING` | `0.20` | Per-user daily Butler LLM spend ceiling (USD) |
| `BUTLER_EXPIRE_TICK_SECONDS` | `60` | Butler TTL expiry worker interval |
