# T12-08 Rollout Fragment — Butler TTL expiry worker + abuse controls

## What shipped

- **`bot/services/butler_budget.py`** — per-user-day budget guard:
  - `ButlerBudgetChecker.is_user_daily_exceeded(session, user_id, spend_fn)` — returns True when user >= ceiling
  - `compute_user_daily_budget_spent(session, user_id)` — thin wrapper around `_query_butler_daily_spend` helper (extracted for testability); SUMs `llm_usage_ledger.cost_usd` via JOIN on `butler_actions.llm_usage_ledger_id` for current MSK calendar day, filtered to `call_type IN ('butler_decision','butler_summary')`
  - Ceiling: `BUTLER_PER_USER_DAILY_USD_CEILING` env var (default `0.20` USD)
  - **C1 (round-2 fix):** `ButlerBudgetChecker` wired into `ButlerService.plan_action` between rate-bucket increments and evidence build; on ceiling hit → rate buckets rolled back + audit ledger row + raises `ButlerActionError(error_kind='budget_exceeded')`

- **`bot/services/scheduler.py`** — TTL expiry worker:
  - `_expire_action_inline(action_id, *, session, action_repo)` — **M1 (round-2 fix):** free function; avoids `ButlerService(None,...)` antipattern
  - `butler_expire_tick_job(bot)` — APScheduler wrapper; gated by `memory.butler.enabled` flag at tick start; bot threaded via `args=[bot]` (T7 FHR F2 pattern)
  - Job ID: `butler_expire_tick`; interval: `BUTLER_EXPIRE_TICK_SECONDS` (default 60s)

- **`bot/db/repos/butler_action.py`** — `get_pending_past_ttl(session, *, now)` with `.limit(BUTLER_EXPIRE_BATCH_SIZE)` — **H2 (round-2 fix):** default 200, env-configurable

- **`bot/db/repos/llm_usage_ledger.py`** — `monthly_cost_usd` gains `call_type: str | None = None` kwarg (C9 / T12-08 spec requirement); **H3 (round-2 fix):** `LedgerRepoProtocol.monthly_cost_usd` signature updated to match

- **`bot/services/llm_gateway.py`** — **H1 (round-2 fix):** `_butler_budget_check` monthly cap now sums `monthly_cost_usd(call_type='butler_decision') + monthly_cost_usd(call_type='butler_summary')` (TODO removed; previously summed all call types)

- **`expire_action` FOR UPDATE NOWAIT** — **M2 (round-2 fix):** coordinates with `_cascade_butler_actions` cascade worker to avoid lock contention

- **`.env.example` / `.env.dev.example` / `.env.production.example`** — **M3 (round-2 fix):** 3 new vars documented

## No migration

Budget tracking uses existing `llm_usage_ledger ↔ butler_actions.llm_usage_ledger_id` JOIN (T12-04 added `expires_at`). No new DB column needed.

## Operator steps (post-deploy)

1. Review the 3 new env vars below in your `.env` / Coolify environment. Defaults are safe for launch.
2. Set `BUTLER_PER_USER_DAILY_USD_CEILING` to the per-user daily ceiling appropriate for your community (default $0.20).
3. No flag to flip — the TTL worker only runs when `memory.butler.enabled = true` (default OFF, controlled by T12-05).

## Env vars added

| Var | Default | Purpose |
|---|---|---|
| `BUTLER_PER_USER_DAILY_USD_CEILING` | `0.20` | Per-user daily Butler LLM spend ceiling (USD) |
| `BUTLER_EXPIRE_TICK_SECONDS` | `60` | Butler TTL expiry worker interval (seconds) |
| `BUTLER_EXPIRE_BATCH_SIZE` | `200` | Max stale actions processed per tick |

## Rollback playbook

Disable `memory.butler.enabled` feature flag (set to `false` via admin SQL or `FeatureFlagRepo.set_enabled`). The TTL worker stops firing immediately on next tick. No data is lost — `butler_actions` rows with `status='pending_confirmation'` simply remain unexpired until the flag is re-enabled.

T12-08 touches `bot/services/butler.py` **zero times** — all changes are in `scheduler.py`, `butler_budget.py`, `llm_gateway.py`, and repos. The `expire_action` method added in T12-04 is called as-is. No line collision with T12-07's `execute_undo`.
