# T12-10 Rollout Fragment — Phase 12 Closure

## What shipped

### FHR fix: scheduler savepoint (HIGH)

`butler_expire_tick_job` in `bot/services/scheduler.py` now uses a savepoint per action
expiry so that a failure on one action does not roll back the entire tick's work. This
mirrors the pattern used in `digest_daily_job` and `cascade_worker_tick`. The fix lands
on commit at HEAD (`8dec11c`) of `feat/p12-t12-10-closure`.

### Code fix: models.py CHECK constraint drift (MEDIUM)

`ButlerActionConfirmation` ORM model in `bot/db/models.py` had a `CheckConstraint`
listing `status IN ('pending','confirmed','rejected','expired','cancelled')` — missing
`'revoked'` which migration 075 (T12-05) added to the live DB. The ORM metadata now
matches the live schema (commit `e7f5188`). Fixes `create_all`-from-metadata drift and
any tooling that validates ORM metadata against DB reality.

**Before:**
```
"status IN ('pending','confirmed','rejected','expired','cancelled')"
```

**After:**
```
"status IN ('pending','confirmed','rejected','expired','cancelled','revoked')"
```
