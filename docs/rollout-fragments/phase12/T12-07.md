# T12-07 Rollout Fragment — Rollback & `/butler_undo`

## What shipped

- **`bot/services/butler.py`** — `ButlerService.undo_action(*, action_id, requester_user_id, is_admin=False, bot=None)`:
  - Acquires `get_for_update` (FOR UPDATE NOWAIT) on the original row → `CascadeInFlightError` on contention (same pattern as `cancel_action`/`confirm_action`).
  - **Authorization first** (criterion 6): actor must be the requester, an admin (verified via `user_repo`), or an `affected_user` on the original action — checked before any state is revealed.
  - **Original row is immutable** (criterion 2): never mutated. The undo is recorded entirely on a NEW child `butler_actions` row with `parent_action_id` → original (criterion 1).
  - Child inherits `evidence_context_hash` + `evidence_ids` + `llm_usage_ledger_id` from the parent (**C10.b** citation preservation; also satisfies `ck_butler_actions_ledger_required_post_plan` since undo spends no LLM budget). Child's own `rollback_kind='not_reversible'` (an undo is not itself undoable; satisfies `ck_butler_actions_executed_has_inverse`).
  - Double-undo guard via `ButlerActionRepo.list_children` — refuses a second undo while an `undo_pending`/`undo_succeeded` child exists.
  - `_execute_inverse` dispatches on the original's `inverse_op_payload['rollback_kind']` (criterion 3):
    - `delete_message` → `bot.delete_message` (chat = `chat_id` for group posts, else `target_user_id` for DM intros)
    - `edit_message` → `bot.edit_message_text` to a neutral retraction notice (`parse_mode=None`; prior text is never stored — privacy)
    - `followup_correction` → `bot.send_message` retraction notice
    - `cancel_pending` → marks the `extraction_candidates` row `rejected` **only if still `pending`** (FOR UPDATE; never clobbers an admin decision)
    - `not_reversible` → no side effect; child recorded `undo_succeeded` (criterion 4)
  - Failure (criterion 5): any exception → child `undo_failed` + content-free structured `error_context` (`rollback_kind`, `exception_type`, `message_id`, `chat_id`) → raises `ButlerUndoError`.
  - New exception `ButlerUndoError(ButlerActionError)` (`error_kind='undo_failed'`), additive.

- **`bot/db/repos/butler_action.py`**:
  - `create()` gains `parent_action_id` / `inverse_op_payload` / `undone_at` kwargs.
  - New `list_children(session, parent_action_id)` for the double-undo guard.

- **`bot/handlers/butler.py`** — `/butler_undo <action_id>` is now real (was a stub):
  - Master-flag + membership gates; usage hint on missing arg.
  - Maps `ButlerUndoError` → commits the audit row + failure message; `forbidden`/`wrong_status`/`cascade_in_flight` → `session.rollback()` + polite message (T12-05 middleware-commit discipline); success → "rollback done" vs "logged, not reversible" keyed off the child's recorded `result_payload`.

## Scope note

Per PHASE12_DESIGN §"/butler_undo", a *separate per-action undo confirmation gate* (inline keyboard before the inverse fires) was discussed. The PLAN §T12-07 acceptance criteria do not require it, so this PR ships direct authorized undo and defers the optional undo-confirmation gate as a Phase 12.5 follow-up.
